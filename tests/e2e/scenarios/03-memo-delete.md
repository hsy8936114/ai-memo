# 시나리오 03: 메모 삭제

- **우선순위:** P1 (높음)
- **대상 URL:** http://localhost:3000
- **근거:** 되돌릴 수 없는 파괴적 동작이므로 확인 창과 실제 삭제 반영을 반드시 검증해야 한다. 또한 다른 시나리오의 정리(Cleanup) 수단이다.

## 사전 조건

- 삭제 전용 메모 `[E2E] 삭제-<타임스탬프>`가 존재한다. (시나리오 01의 절차로 먼저 생성)
- **시드 메모나 사용자 메모는 삭제 대상으로 쓰지 않는다.** 연결된 DB는 실제 데이터이다.

## 절차 및 기대 결과

| #   | 동작                                                         | 기대 결과                                                         |
| --- | ------------------------------------------------------------ | ----------------------------------------------------------------- |
| 1   | 메인 페이지 접속, `총 N개의 메모`에서 N 기록                 | N 확보                                                            |
| 2   | 대상 카드의 `삭제` 버튼 클릭                                 | `정말로 이 메모를 삭제하시겠습니까?` 확인 창이 뜬다               |
| 3   | 확인 창에서 **취소(dismiss)**                                | 메모가 삭제되지 않고 카드와 개수 N이 그대로다                     |
| 4   | 다시 `삭제` 클릭 후 확인 창에서 **확인(accept)**             | 카드가 목록에서 사라진다                                          |
| 5   | `총 N-1개의 메모` 확인                                       | 개수가 1 감소한다                                                 |
| 6   | 삭제한 제목으로 검색                                         | `검색 결과가 없습니다`가 표시된다                                 |
| 7   | 페이지 새로고침                                              | 삭제된 메모가 다시 나타나지 않는다 (영속화 검증)                  |

## 변형 케이스 (같은 시나리오의 하위 확인)

- 카드를 클릭해 연 **상세 보기의 `삭제` 버튼**으로도 동일하게 삭제되고 모달이 닫힌다. (확인 창 문구 동일)

## 참고 / 주의

- 확인 창은 브라우저 네이티브 `confirm`이므로 Playwright에서 `page.on('dialog', ...)`로 처리하고, **클릭 전에 핸들러를 등록**해야 한다.
- 이 시나리오는 `전체 삭제(clearAllMemos)` 동작을 **다루지 않는다.** 실제 DB 전체가 지워질 수 있으므로 자동화 대상에서 제외한다.
- 삭제 실패 시 화면에 `메모를 삭제하지 못했습니다.` 오류가 표시되어야 한다. (P3, 네트워크 차단 등 별도 케이스)
